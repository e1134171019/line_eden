# 獎學金來源納入審查規則

新增網站不得直接加入正式監測。每個候選來源必須先完成審查，並在 `AdditionalScholarshipSource.review_reason` 留下不含個人資料的納入理由。

## 私人資格基準

來源相關性依執行環境中的私人使用者設定評估。公開程式庫只保存審查結論，不保存學校、戶籍、成績、收入、特殊身分或其他個人資格細節。

## 必要條件

候選來源必須同時符合：

1. 網址可由 GitHub Actions 安全連線。
2. 解析器能取得具體獎學金公告，而不是只有導覽頁或空頁。
3. 與既有來源相比具有獨特價值，不能只是同一方案的完全重複入口。
4. 來源不是僅限其他學校在校生使用的校內獎學金平台。
5. 必須有明確且不含敏感資料的 `review_reason`。

## 優先納入

- 與私人設定中的專業方向直接相關的官方獎學金
- 私人資格確認可申請的地方政府或全國性大專獎學金入口
- 能穩定產出多個校外方案的公告中心
- 能補足現有來源未涵蓋企業或基金會方案的網站

## 直接排除或延後

- 已由指定方案或其他官方來源完整監測的重複入口
- 只服務該校在校生、且沒有校外公開方案的校內平台
- 即時稽核為零筆，且無固定官方方案頁可作安全追蹤
- TLS、DNS、HTTP 或解析結構持續失敗，且沒有足夠獨特價值值得維護專用 collector
- 大量轉載但新增方案幾乎全部被既有來源去重的低增益網站
- 私人設定目前不符合，且資格短期內不會改變的方案
- 需等年級、畢業身分或研究階段改變後才符合的方案，保留為延後監測候選

## 驗證流程

1. 搜尋候選網站並人工審查資格與獨特性。
2. 以私人設定做相關性判斷，但不將個資寫入公開程式庫。
3. 執行候選來源第一頁增量審查。
4. 執行完整來源契約測試。
5. 檢查解析筆數、去重後增益與來源健康狀態。
6. 通過品質測試與來源契約後才合併到 `main`。

來源數量不是目標；提高符合資格方案的發現率才是目標。
